# v0.3.0

## Summary

- Removed Qdrant entirely. Pinecone is now the sole vector backend; the `VECTOR_BACKEND` switch and all `QDRANT_*` settings/env vars are gone.
- App lifespan now unconditionally initializes Pinecone at startup; missing `PINECONE_API_KEY` is a hard error instead of a silent fallback.
- Confirmed the FastAPI Swagger UI surface (`/docs`, `/redoc`, `/openapi.json`) renders all three routers (Health, Knowledge, Scan); no application code change required for it.
- Knowledge upload service no longer runs the `VECTOR_BACKEND==pinecone` runtime check (always true now).
- RAG retrieval (`retrieve_for_chunk`) gates on Pinecone readiness *before* the embedding model is loaded — keeps unit tests hermetic and avoids unnecessary HF Hub downloads when no live index is available.
- Test infrastructure: `tests/conftest.py` neutralizes the Pinecone init in the FastAPI lifespan so `TestClient` never contacts a real index. Tests that exercise Pinecone behavior monkeypatch `get_pinecone_index` directly.

## Breaking changes

- `GET /health` response no longer carries `qdrant_status` or `vector_backend`. Only `pinecone_status` remains for vector-store health.
- `GET /api/v1/knowledge/status` response no longer carries `vector_backend`. `pinecone_index` and `pinecone_namespace` are now required (non-nullable) `str` fields.
- The deprecated test `test_knowledge_document_upload_requires_pinecone` was removed (the guard it asserted on no longer exists).
- `qdrant-client` removed from `requirements.txt`. Qdrant service + `code_scanner_qdrant` volume removed from `docker-compose.yml`.

## Rationale

The dual-backend abstraction was costing more than it bought: every consumer of the vector store had to thread a `VECTOR_BACKEND` check, the lifespan branched on it, the health endpoint reported two parallel statuses, and tests had to set `VECTOR_BACKEND=none` purely to opt out of network. Committing to Pinecone collapses the whole stack into a single linear path — Pinecone is initialized once, used directly, and surfaced through one health field. The two real risks (tests hitting a live index, and embedding-model downloads triggered by a no-op RAG call) are mitigated explicitly: the test conftest monkey-patches the lifespan's Pinecone hooks, and `retrieve_for_chunk` checks Pinecone readiness *before* invoking the embedder, preserving the previous "no backend → empty bundle, no work done" semantic.

Swagger required no code changes — FastAPI serves it by default at `/docs` because `app/main.py` does not pass `docs_url=None`. This release treats Swagger as a confirmation point only; UI polish (server URLs, security schemes, examples) is deliberately out of scope.
