# v0.1.0

## Summary

Initial Shield backend: FastAPI scan API with LangGraph analysis pipeline (static analysis as primary detection, single LLM refinement node, validation and aggregation), PostgreSQL/SQLite persistence, optional Qdrant RAG for security corpus, Redis hooks, TypeScript CLI, tests, and corpus ingest script.

## Changes

- **App layout:** `app/main.py` factory, `core/` (config, database, redis, qdrant, logging, exceptions, dependencies), `controllers/` (health, scan), `models/`, `repositories/`, `schemas/`, `services/` mirroring movie-agent style.
- **API:** `POST /api/v1/scan`, `GET /api/v1/scan/{id}`, `WS /api/v1/scan/{id}/stream` with typed stream events.
- **Analysis:** LangGraph graph (`normalize` → `static` → `risk_select` → `rag_llm` → `validate`); regex/static signals, risk gating, Qdrant retrieval when enabled, stub or HF LLM backend, validation merge rules, deduplication.
- **Infra:** `docker-compose.yml` (Postgres, Redis, Qdrant), `alembic` initial migration, `requirements.txt` + `requirements-ml.txt` for optional ML stack.
- **Data:** `data/security_corpus/` sample OWASP-oriented markdown; `scripts/ingest_security_corpus.py` for Qdrant upsert (requires ML + Qdrant).
- **CLI:** `cli/` TypeScript client — file discovery, `ScanRequest` POST, WebSocket stream.
- **Tests:** SQLite test DB, Qdrant/Redis disabled in tests; unit + integration coverage.

## Rationale

- **Static-first + one LLM node** matches the security-engine principle: deterministic signals drive truth; the LLM only refines and explains.
- **Split ML requirements** keeps CI and lightweight installs fast while full RAG/ingest remains one `pip install -r requirements-ml.txt` away.
- **`QDRANT_ENABLED`** allows local and test runs without a Qdrant process while production can enable full RAG.
