# v0.2.0

## Summary

- Added provider-routed LLM refinement across Hugging Face, Groq, OpenAI, local transformers, and the deterministic stub provider.
- Added Pinecone-backed vector storage for RAG and REST endpoints for uploading knowledge documents/files for Hugging Face embedding into Pinecone.
- Added vector backend health/status reporting and tests for routing, Pinecone retrieval, and knowledge upload behavior.

## Areas / Files Touched

- `app/core/config.py`, `.env.example`, `requirements.txt`
- `app/services/analysis/llm_providers/`, `app/services/analysis/llm_refinement.py`
- `app/core/pinecone_core.py`, `app/repositories/pinecone_repo.py`, `app/services/analysis/vector_stores/`
- `app/controllers/knowledge_controller.py`, `app/schemas/knowledge.py`, `app/services/knowledge_ingest_service.py`
- `app/controllers/health_controller.py`, `app/schemas/common.py`, `app/main.py`
- `scripts/ingest_security_corpus.py`, `tests/`

## Rationale

This release separates model selection from the scan graph so deployments can tune for speed or quality without changing analysis code. Pinecone support uses the same chunk/embed/upsert contract as the existing corpus flow, keeping RAG ingestion auditable through namespaces, source metadata, document versions, and content hashes while avoiding secret exposure in status/health responses.
